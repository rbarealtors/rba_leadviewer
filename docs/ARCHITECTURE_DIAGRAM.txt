│  ├─ Ad Group dropdown

❌ Mobile becomes nightmare (wrapping, overflow)

   const [adGroup, setAdGroup]
   const [customFrom, setCustomFrom]
   const [customTo, setCustomTo]

   → State grouped by TIER (how user experiences it)


RENDERING OPTIMIZATION
═══════════════════════════════════════════════════════════════════════════════

CURRENT
───────
Lead change → LeadsClient re-renders → FiltersBar re-renders
            → Segment buttons re-render (duplicate)
            → Stats cards re-render
            → LeadsTable re-renders

Unnecessary renders of duplicate button sets


PROPOSED (with React.memo)
──────────────────────────
Lead change → LeadsClient re-renders
            → PrimaryFilterBar re-renders (memoized, only if primary state changes)
            → AdvancedFiltersPanel re-renders (memoized, or not if collapsed)
            → ActionBar re-renders (memoized, only if export state changes)
            → LeadsTable re-renders

Precise renders only for affected components

DECISION CHECKLIST BEFORE BUILD
═══════════════════════════════════════════════════════════════════════════════

□ Do users actually use Campaign/AdGroup filtering?
  → Check analytics
  → If <5% usage, consider removing from Advanced panel entirely

□ Is "Needs review" a view mode or a status filter?
  → Current: View mode (toggles display)
  → Alternative: Status column filter
  → Affects: Where it appears in Tier 1

□ Mobile priority: Drawer or inline?
  → Proposed: Drawer when Advanced panel opens on mobile
  → Alternative: Always inline (takes more space)

□ How often do users export?
  → If <5%: Move to "More" menu
  → If >20%: Keep prominent in ActionBar

□ Do stats cards need to be on the main view?
  → Proposed: Below filters, above table
  → Alternative: Sidebar / separate dashboard page

Once answered, implementation is straightforward.
